*[Ассистент нашёл причину в маппинге и проверил исправление: 20 прогонов подряд на WireMock для запросов без ключа и с неверным ключом.]*

**Ассистент:**

> Я исправил заглушку `error-2006-invalid-key.json` в вашей папке. Теперь запрос без ключа возвращает 1002, а с неверным ключом — 2006: я прогнал оба запроса по 20 раз на WireMock, ответы каждый раз верные.
>
> **Что было не так.** В условии «ключ не равен валидному» (`key doesNotMatch`) WireMock считает подходящим и запрос, где параметра `key` нет вообще. Поэтому запрос без ключа подходил сразу под две заглушки, 1002 и 2006, с одинаковым приоритетом. Какую из них выбрать, WireMock не гарантирует. У меня случайно отвечала 1002, а у вас — 2006.
>
> **Что изменил.** Понизил заглушке 2006 приоритет с 2 до 4. Теперь сначала проверяется, передан ли ключ вообще, и только потом — правильный ли он. Так же проверяет и настоящий API.
>
> Остальное в вашем прогоне работает как задумано: все четыре города совпали по всем 9 полям, остальные 4 ошибки прошли.

## 4. `Task '#' not found`

**Я:**

> При вызове ./gradlew clean test            # прогон тестов
>  вылетает Task '#' not found in root project 'weather-api'.

*[Ассистент переписал раздел запуска в README: каждая команда в своём блоке, пояснение над ним.]*

**Ассистент:**

> Это не ошибка проекта. Вы скопировали команду из README вместе с комментарием `# прогон тестов`. В zsh, стандартной оболочке macOS, `#` в интерактивном режиме не считается началом комментария. В итоге Gradle получил `#`, `прогон` и `тестов` как имена задач и не нашёл задачу `#`.
>
> Запускайте без комментария: `./gradlew clean test`. Если хотите, чтобы zsh понимал такие комментарии, добавьте в `~/.zshrc` строку `setopt interactivecomments`.
>
> Чтобы на это не наткнулся тот, кто будет проверять задание, перенёс комментарии в README на отдельные строки.

## 7. `allureReport` падает на `copyCategories`

**Я:**

> ```
> ./gradlew allureReport
> > Task :copyCategories FAILED
> * What went wrong:
> A problem was found with the configuration of task ':copyCategories' (type 'CopyCategories').
>   - In plugin 'io.qameta.allure.gradle.adapter.AllureAdapterBasePlugin' type 'io.qameta.allure.gradle.adapter.tasks.CopyCategories' property 'markerFile' is not writable because '/Users/balbart/Documents/Repos/weather-api/build/copy-categories/copyCategories' is not a file.
> ```

*[Ассистент открыл исходник задачи CopyCategories в allure-gradle 2.12.0 и проверил, в какой версии плагина это исправлено.
Воспроизвёл ошибку на Gradle 8.14.3 с копией задачи из плагина и проверил на ней обходной путь.]*

**Ассистент:**

> Исправил: добавил обходной путь в `build.gradle.kts` у вас в проекте.
>
> **В чём было дело.** Это баг самого плагина Allure для Gradle 2.12.0, а не нашего проекта. Задача `copyCategories` объявляет служебный выход как файл, а создаёт на его месте каталог. Первый запуск проходит. При следующем запуске, когда задачу нужно выполнить заново (у нас — после изменения `categories.json`), Gradle находит каталог там, где ждал файл, и останавливает сборку.
>
> **Что я сделал.** Перед `copyCategories` теперь запускается задача, которая удаляет этот каталог, поэтому ошибка не появится, сколько ни запускай сборку.
>
> В самом плагине баг исправлен только в версиях 4.x. Обновляться на них я не стал: они переходят на Allure 3 и требуют в тестах Java 17 или новее, а у нас по условию JDK 19.
